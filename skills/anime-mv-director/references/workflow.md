# 完整流程

每一階段都有「關卡」。關卡沒過，不往下做。

## 0 準備

收集：
- 歌曲音軌（mp3）、歌詞（日文＋中譯，分段標記）。
- 原作文本（劇本、小說），整理成可搜尋的格式（`行號|說話者：台詞`）。
- 角色立繪、原版 CG、道具設定圖。
- 可用工具與額度：本機 ComfyUI（哪些模型、哪些角色／畫風 LoRA）、Codex／GPT 生圖、即夢、MiniMax H3、Midjourney……

關卡：
- 每張參考圖的來源要確認。「官方圖」可能其實是同人圖（第一支就踩過）。
- 列出工具清單，標明每個工具的用途；不要邊做邊換。

## 1 概念與分鏡

1. 讀原作，抓出和歌詞情緒相符的場景，附原文行號。
2. 抓歌詞時間軸：每句起訖秒數、段落（主歌 A／副歌 S／間奏）、BPM。
3. 寫概念：主角是誰、誰不露臉、貫穿意象（燈、影子、道具）、色彩、分寸。
4. 寫鏡頭表 `storyboard/shots.json`：每鏡的時間、畫面、來源（原 CG／生圖／動畫）、提示詞。

原則：
- **不必逐句硬扣歌詞**。情緒連貫優先，硬扣的鏡頭常被退回。
- 一句歌詞約 4 拍，鏡頭長度以拍為單位。

關卡：使用者通過概念和分鏡。

## 2 定畫風（一次定死）

1. 選基準：通常是原版 CG，所有生成圖都往它靠。
2. 每種可能的來源各出 3 張測試圖，例如本機模型＋角色 LoRA、GPT 生圖附參考圖、以 CG 為底圖生圖。
3. 使用者選一套，寫進專案說明：模型、畫風 LoRA 與權重、角色 LoRA 與權重、統一工序（例如所有生成圖最後都過一次「Anima＋star，denoise 0.4」的圖生圖）。
4. 瞳色、髮型等容易飄的特徵寫進固定提示詞，負面詞排除其他瞳色。

關卡：畫風定案後不再換工具。真的要換，要回到這一步重新測試，而不是在生圖途中換。

## 3 動畫可行性測試

在大量生圖前，先拿一張圖做一段 5 秒動畫，走完「生成 → 接進時間軸 → 60fps 小樣」全程：
- 確認工具實際輸出的幀率和解析度。
- 確認慢動作生成的速度是否自然。
- 確認臉會不會變。

關卡：使用者看過小樣，選定動畫工具和做法（見 animation.md）。

## 4 生圖與審圖

- 審圖資料夾：`審圖_分段/<段>/<鏡號>_<來源>/`，使用者刪掉不要的，留下的就是可用的。補圖時不要把使用者刪過的檔名放回去。
- 每張交出去前，照 review-checklist.md 放大檢查。
- 定稿圖用 SeedVR2 去噪（`enhance.py --mode seedvr2`），合成時會自動改用 hd 版。
- 使用者自己做的素材優先使用。

關卡：分段審圖全部通過，才進合成。

## 5 動畫

- 只在動畫能讓意思更清楚時才做；沒必要不要硬做。
- 人物臉部盡量不動，只動頭髮、衣物、環境。
- 每段先出 60fps 小樣，通過後才接進時間軸。

## 6 合成

- 一段一個時間軸（s0、a1、s1…），分段出小樣審。
- 字幕：副歌直書、主歌依留白擺放；中譯用與時代相符的字（例如古風用繁體）。
- 片名、片尾字卡、片尾配樂也在這一步。

## 7 出片

- 使用者確認後才輸出完整版，用新檔名。
- 主檔 1080p60（h264_nvenc cq 16，約 1.2GB／4.7 分鐘）。
- Discord 等有 1GB 上限的平台：從主檔轉 720p60 或 1080p30（約 18Mbps，約 600MB）。

## 看片回饋

- 一律記進 `待改清單.md`（時間、鏡頭、問題、改法、狀態）。
- 使用者說「一起改」才動手；改完出小樣，確認後才重出完整版。
